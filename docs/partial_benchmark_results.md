# Report obligations remove acquisition headroom in the design pilot

Confirmation was stopped at the user request after all 4,096 captures and 129,037 of the planned 262,144 controller rows. The partial rows are a checkpoint, not a confirmation estimate; no final confirmation aggregate or figure is available. Both interrupted attempts and measured stop resources are retained. [Checkpoint identity and status](../benchmarks/evidence_policy_checkpoint.json) records the portable scientific archive checksum. The results below concern the completed design pilot and tune selection.

The frozen design cohort contains 96 objects at four relative horizons, giving
384 requests. At shared budget 40, each control certified 380 decisions and
completed 255 full reports. Every completed full report cost exactly 26 imposed
shared units. EC2 and compiled execution had identical full-report cost. This is
a negative result for cheaper completed reports under this policy, report contract
and cost model, not a statement about every scientific workflow.

| Control | Decision-only mean spend | Full-report mean spend |
|---|---:|---:|
| Conservative eager | 29.0234 | 29.0234 |
| Compiled design order | 15.0703 | 29.0234 |
| Direct nullable fail-closed | 15.0625 | 29.0182 |
| Support-complete EC2 | 15.5443 | 29.0234 |

Means retain every request, including unresolved decisions and incomplete reports.
These design runs used a provisional fixed order and a declared uniform logical
prior. Decision-only EC2 minus compiled spend was +0.474 units (95% object-bootstrap
interval [0.430, 0.518]); the full-report difference was 0 [0, 0]. Bootstrap used
2,000 object resamples with seed 20261102. No eager-only comparison establishes
scheduler novelty or full-report savings.

Classification, anomaly diagnostics, consulted context and photometry are all
necessary for a completed blind report in the supplied conservative domain. They
cost 26 shared or 48 independent units. Offline triggered history is unavailable
and prevents completion. A simple compiled order attains the completed-report
floor. Below the relevant floor, an analytical zero-query abstention control has
zero task completion and zero acquisition spend; secondary infeasible budgets
cannot establish an acquisition improvement against that control.

For each clean control, 380 emitted decisions had an independent successful-data
software-policy reference, with zero disagreements; four requests had no measured
reference because relevant history was unavailable. Across 96 objects, zero
independent errors on referenced emitted looks gives a nominal two-sided 95%
exact upper bound of 3.77% for that object event. Undefined or unemitted looks are
outside this empirical bound. This does not measure astronomical accuracy or
prove universal safety. Independent finite-domain and AST checks verify conditional
software behavior; the domain still overapproximates realizable scientific states.

The predefined missing-tool and scope interventions produced all 30,720 requested
comparison rows, with zero execution failures, unsupported emissions or available
reference disagreements. Each scenario retains all 384 requests. All controls
completed zero full reports when a mandatory source was removed or invalidated.
The history-only mask removed no preexisting valid history and retained 255 report
completions; that is an eligibility result, not a measured history-failure effect.

The one anomaly-mask difference is query order: for ZTF20abchbds at horizon 100,
compiled execution obtained photometry/context/classification, while direct
fail-closed execution stopped at unavailable anomaly before classification. The
classification evidence already fixes the relevant nullable branch. This is not
an enumeration-coverage advantage over an equally informed nullable evaluator.
The deliberately incorrect missing-as-negative diagnostic used the same compiled
order, cost and profiles over seven masks (5,376 rows). It produced 384/384
unsupported singletons for missing photometry, about 198–200/384 for several other
masks, and 4/384 for history-only. These are controlled support violations, not
estimates of real fault frequency.

Separate literal pinned-source replay on the same captured-prefix payloads covered
clean inputs plus seven masks (3,072 rows). The function returned 384 legacy Report
objects on clean inputs, but only 255 meet the new report obligations and four
verdicts lack a logical certificate with unavailable relevant history. Under a
missing-photometry intervention it returns 384 unsupported singletons. Literal
outputs, exceptions and tool calls are retained. This is not a live replay of the
old default-100 context pipeline, a fair acquisition-cost control, or astronomical
ground truth. Missing history was never assigned an invented measured value.

Tuning is complete for configuration selection only: 256 objects, 1,024 requests,
120 fixed orders in each of 16 profile/cost/budget cells, scored with actual runtime
completion on all 32 tool subsets. At budget 60, selection scores are 998 certified
decisions and 684 reports per 1,024 inputs. These are fitting objectives, not
independent confirmation results. The selected orders and exact prior are portable
benchmark resources; reproduction must pass the prior explicitly. No comparative
tune replay or confirmation has been performed.

A separate full-logical-support exact-DP attempt exceeded the declared 30-second
root limit for both profiles. All 768 comparator rows remain failures; no optimum
or saving is claimed. Small independent finite DP fixtures passed without proving
full-support tractability. Clean replay used 60.7 CPU seconds, mask/scope replay
567.6, the bounded negative diagnostic 64.9, literal replay 2.5, tuning selection
99.6 and capped DP 69.1. These are controller/selection times, not live acquisition
latencies. Actual captured backend work is recorded separately. Source hashes
were verified and unchanged during each run.

A history-availability guard could stop some impossible reports earlier. It is an
unimplemented ordinary abstention optimization and would require a matching
control, full failure-inclusive accounting and separate decision coverage. It
cannot lower the completed-report floor here. No global optimality, live inference
saving or new acquisition method is claimed.

[Reproduction and scope](partial_benchmark.md) describe the interfaces, costs and
artifacts. Raw observations, request rows, resource/source manifests and bootstrap
results are retained with the study. No confirmation data, application LLM trials
or follow-up utility labels are included. Source arrays overlap classifier
training/calibration. EC2/SBFE are established work. No adaptive-acquisition advantage was demonstrated
in the completed design study; these results validate software-policy behavior,
not astronomical utility or a new algorithm.
